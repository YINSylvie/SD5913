# Why are we here?

As an animation student, I am not learning programming because I want to become a programmer. My main interests have always been games, visual art, and virtual reality. I enjoy designing environments and visual effects, and I am also interested in how people move, look, and interact within digital spaces. However, when I started using Unreal Engine and Unity to make my projects, I gradually realized that if I did not understand programming at all, I could not truly understand the creative medium I was working with.

This question has become more complicated now. In 2026, AI can already generate working code from a simple sentence written in everyday language. In the future, writing code itself may no longer be a scarce skill. So, as an artist, why should I still learn programming?

My answer is not simply that “programming is important.” I am not learning programming to compete with machines in writing code faster or more accurately. I am learning it so that I can understand, evaluate, and control digital media.

I experienced this quite directly while working on my VR project, Infinite Cloud Atlas. It is a first-person narrative VR game in which the player takes on the role of a “Memory Keeper” who enters a space where forgotten memories are stored. I experimented with point clouds, 3D scanning, and Unreal Engine to transform real-world spaces into a fragmented and unstable digital environment.

During the process, I realized that making something work and making something work the way I want it to are two completely different things. For example, I could tell an AI, “Make the player grab an object in VR and put it into an archive.” AI might quickly generate a set of code that looks perfectly reasonable. But that does not mean it understands my design.

What I really need to think about is: Why does the player need to grab this object? Should the speed of the interaction affect the state of the memory? When the object disappears, should it vanish instantly or slowly dissolve? How should sound and visual changes respond to the player’s actions? And if the player does not interact with the object as expected, how should the system respond?

These are no longer simply questions about how to write code. They are design questions. But if I know nothing about programming, it becomes much harder for me to judge whether these ideas can actually be implemented, or to understand why a system is not behaving the way I intended.

This has led me to think that the value of programming for an artist may not lie in the code itself. Instead, it allows artists to understand their creative medium more deeply.

Painters need to understand the properties of paint. Photographers need to understand light and lenses. Animators need to understand movement and timing. In the same way, someone creating with a game engine needs to understand the basic logic of computers and interactive systems.
